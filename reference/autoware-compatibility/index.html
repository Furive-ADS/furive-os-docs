    Autoware GPU·CUDA·드라이버 호환 기준¶

    Autoware를 설치할 main PC의 현재 판정은 다음 명령으로 확인합니다.

    furive status

    출력의 Autoware 호환, 드라이버 기준, 현재 드라이버가 각각 판정 단계와 선택 CUDA, 최소·권장 NVIDIA driver, 현재 host의 충족 여부를 보여줍니다. Furive OS 자체와 GPU Autoware의 상태는 분리되어 있으므로, GPU 호환이 준비되지 않아도 GPU가 필요 없는 Furive 기능과 furive 명령은 사용할 수 있습니다.

    기준 파일¶

    config/autoware-compatibility.yaml이 호환값의 유일한 원본입니다. config/capability-profiles.yaml의 플랫폼은 이 표에 있는 실행 환경 하나를 선택할 뿐, driver나 image 값을 복사해 소유하지 않습니다.

    현재 표는 다음 축을 함께 검증합니다.

    열 의미
    os, os_version 지원하는 host 배포판과 버전
    architecture CPU 제품명이 아니라 컨테이너와 package를 결정하는 amd64/arm64 아키텍처
    gpu 현재 CUDA image가 요구하는 NVIDIA runtime
    cuda host toolkit 버전이 아니라 Autoware image CUDA와 driver CUDA 호환 상한의 계약
    minimum_driver 해당 CUDA image를 실행할 수 있는 NVIDIA host driver 하한
    recommended_driver 현장 container 검증을 통과한 우선 목표. 이미 최소 조건을 만족하는 driver의 강제 업그레이드 근거는 아님
    image 해당 행에 묶인 Autoware Dev Container image

    GPU 제품명은 같은 이름 안에서도 revision이 달라질 수 있어 1차 키로 쓰지 않습니다. general_pc_compute_capability가 NVIDIA Compute Capability 범위를 CUDA 행에 연결합니다. 여러 NVIDIA GPU가 서로 다른 CUDA 행을 요구하면 한 Autoware container로 안전하게 만족시킬 수 없으므로 차단합니다.

    세 단계 판정¶

    1. 1차 매핑: 차량 플랫폼의 정확한 환경 또는 실제 GPU Compute Capability가 표의 한 행을 선택합니다. OS, CPU architecture, GPU runtime, CUDA, driver 하한과 image가 모두 일치해야 합니다.
    2. 2차 자동 판정: 새 PC처럼 정상 동작하는 driver가 없어 Compute Capability를 아직 읽지 못할 때만 사용합니다. 표가 허용한 host/driver 범위와 ubuntu-drivers devices가 보고한 실제 GPU 지원 package의 교집합에서 exact package/version을 고릅니다. ubuntu-drivers autoinstall과 recommended 결과를 그대로 따르지 않습니다. 재부팅 뒤 다시 1차 매핑하고 NVIDIA container smoke test로 확정합니다.
    3. 3차 차단: 표에 없는 OS·architecture·GPU, 서로 충돌하는 다중 GPU, CUDA/driver 하한 미달, GPU 지원 package 없음, image CUDA 불일치 또는 smoke test 실패는 임의의 낮은 image나 다른 architecture로 우회하지 않습니다. Autoware 설치만 중단하고 원인과 관측값을 출력합니다.

    기존 driver가 1차 기준을 만족하면 유지합니다. 설치된 package가 있으나 교체가 필요하면 bootstrap의 초기 계획과 설치 로그에 이유, 기존 package와 설치할 exact package/version을 보여준 뒤 진행합니다. Furive가 driver를 설치한 경우에는 재부팅 뒤 로그인이나 추가 sudo 입력 없이 부팅 서비스가 1차 재검증과 Autoware 준비를 마칩니다.

    표를 바꿀 때¶

    새 행은 “설치 가능해 보이는 조합”이 아니라 실제 Autoware image와 NVIDIA container smoke test를 통과한 조합만 추가합니다.

    1. compatibility_matrix에 OS, architecture, GPU, CUDA, driver 하한·권장값과 exact image를 한 행으로 추가합니다.
    2. 일반 PC의 새 GPU 범위가 필요할 때만 general_pc_compute_capability에 겹치지 않는 구간을 추가합니다.
    3. 차량 플랫폼이 그 환경을 고정해야 할 때만 capability-profiles.yaml의 autoware_host에서 기존 행을 선택합니다.
    4. 작은 정책 테스트와 전체 계약 검사를 실행합니다.
    pytest -q tests/release/test_autoware_devcontainer_policy.py \
  tests/release/test_autoware_install_contract.py
./furive check

    표에 새 GPU 모델명 목록, host CUDA toolkit 설치, 별도 autoinstall 예외를 추가하지 않습니다. 새 조합이 현재 축으로 표현되지 않는다면 먼저 어떤 하드웨어 속성이 CUDA 실행 가능성을 실제로 바꾸는지 확인한 뒤 그 속성을 이 파일 한 곳의 스키마에 추가합니다.
