    보안·개인정보 기준¶

    이 문서는 접근 정보·권한·데이터·차량 제어·원격 업데이트·배포 서명을 바꾸거나 고객용 normal을 준비할 때만 읽는 참고 자료입니다. 일반 기능 개발의 시작 문서가 아닙니다.

    세 가지 공개 개념¶

    개념 기본 동작
    접근 제어 장비와 배포 버전을 확인하고 접근 정보는 필요한 프로그램에만 전달
    데이터 사용 로컬 녹화·외부 전송·자동 삭제는 직접 켜기 전까지 꺼지고 HMI는 기본적으로 같은 PC에서만 연결
    안전한 업데이트 검증된 차량 버전만 준비하고 실패하면 이전 정상 버전으로 복구

    인증서 형식, 내부 상태, 서명 파일과 호환 경로는 구현 세부입니다. 사용자 설정으로 다시 만들지 않습니다.

    단계별 최소 기준¶

    단계 필요한 것
    일상 개발 실제 접근 정보·개인정보를 쓰지 않기, 변경 범위 테스트, 저장소 비밀값 검사
    한 차량 test 바꾼 경계의 실제 동작과 복구, 실제 데이터를 쓴다면 담당자 승인
    고객용 normal furive check, 운영 접근 키 검토, 해당 데이터 흐름의 고객 배포 승인

    ISO, ISMS, 자동차 규정이나 고객별 계약 증적은 적용 시장·법인 역할·계약이 정해진 뒤 선택합니다. 미래 인증 전체를 일상 개발의 완료 조건으로 사용하지 않습니다.

    현재 강제하는 것과 강제하지 않는 것¶

    구분 현재 기준
    코드가 강제 main↔edge 장비 확인과 암호화 연결, 접근 정보 파일 보호, 녹화·외부 전송의 직접 활성화, 업데이트 내용·대상·복구 확인, Git 비밀값 검사
    운영자가 해야 함 실제 접근 키 발급·전달·교체, 고객 데이터 처리 승인, 접근 검토, 사고·백업·삭제 기록
    아직 제공 안 함 법적 동의 자동 판정, 조직 인증, 원본 rosbag·영상의 저장 암호화, 모든 외부 프로그램·사용권 목록, 패키지별 완전 격리

    기술적으로 기능을 켠 사실은 정보주체의 동의나 다른 법적 근거를 증명하지 않습니다. 코드 테스트 통과도 실제 운영 key와 GitHub 보호 설정이 배포됐다는 증거가 아닙니다.

    추가 검토를 여는 변경¶

    다음 중 하나를 바꿀 때만 이 문서의 관련 항목을 검토합니다.

    • 접근 정보, 신뢰할 인증 기관, 원격 접근 또는 패키지 권한
    • 녹화, 저장, 외부 전송, 지도·API·NAS 연계 또는 삭제
    • CAN 송신과 다른 차량 제어
    • 원격 업데이트, 배포 버전 서명, 설치·복구 또는 설정 변환
    • 실제 차량에서 쓰는 외부 프로그램, Docker 이미지 또는 출처 기록

    해당하지 않으면 N/A 한 줄이면 충분하며 새 설정, 상주 프로그램, 동의 처리 프로그램이나 상태 파일을 만들지 않습니다.

    normal 발행 확인 항목¶

    기존 문서와 검증 기록의 식별자는 다음 표 하나에서 유지합니다. 모든 변경에 열 항목을 전부 요구하지 않고 바뀐 경계와 배포 단계만 확인합니다.

    ID 확인
    SEC-01 credential을 source·log에 넣지 않고 필요한 구성요소에만 전달
    SEC-02 로컬 녹화·외부 API·NAS 자동 전송·전송 후 삭제는 명시적 활성화 전까지 동작하지 않음
    SEC-03 package와 host service가 필요한 권한만 사용
    SEC-04 OTA 대상·내용·시작 확인·이전 정상 버전 복구가 일치
    SEC-05 변경된 production dependency의 중요 취약점과 예외 확인
    SEC-06 취약점을 비공개로 신고하고 대응할 경로 유지
    SEC-07 main과 edge가 역할·차량에 맞는 서로 다른 장비 신원을 사용
    SEC-08 실제 데이터의 목적·처리근거·수신자·보유·삭제를 고객 배포 전에 승인
    SEC-09 release component와 고정 image의 생성·출처 증적을 변조 없이 결박
    SEC-10 고객용 release 변경이 review와 제한된 CI 권한을 거침

    SEC-08은 조직의 고객 배포 승인자가 소유합니다. package나 Dashboard가 법적 승인 상태를 별도 config로 복제하지 않습니다.

    개인정보와 차량 데이터¶

    위치, 영상, 차량 ID, 주행 기록과 log가 사람·계정·고객과 연결될 수 있으면 고객 시험 전에 다음 다섯 가지를 한 장의 배포 기록에 남깁니다.

    1. 목적과 필요한 데이터
    2. 수신자와 처리 국가
    3. 보유기간과 삭제 방법
    4. 고지·동의 또는 다른 처리근거
    5. 승인자와 변경일

    현재 주요 경계는 다음과 같습니다.

    기능 안전한 기본값 고객 배포에서 확인할 것
    Data Logging·NAS 로컬 녹화, NAS 사용·자동 upload·upload 후 삭제 꺼짐. 전송에는 완전한 대상·credential·HTTPS·인증서 검증 필요 topic·영상 범위, local/NAS 보유·삭제, storage·backup 보호
    Autonomy Studio 안전한 endpoint와 credential이 모두 없으면 위치 수집·전송·재전송 queue를 시작하지 않음 계정·위치·경로·event 수신자, 국가, 보유·철회
    Dashboard 지도 build token이 없으면 외부 지도·검색 요청 없는 offline 화면 token이 있는 배포의 좌표·검색어 수신자와 고지
    HMI 연동 관리 실행은 같은 PC의 고정 연결기만 사용하고, HMI 설정 변경은 외부 API·자동 upload를 켜지 않음 같은 PC의 다른 process를 아직 인증하지 않는 한계와 고객 HMI binary의 source 일치·외부 통신을 확인

    사용자가 자신의 PC에 Data Logging을 설치하고 자신의 NAS만 대상으로 설정한 기본 경로에서는 Furive가 녹화 원본을 수신하거나 원격으로 읽지 않습니다. 이 경우 PC·NAS 계정, 공유 폴더, backup, 보유기간과 삭제의 운영 책임은 사용자 또는 고객 운영자에게 있습니다. Furive 원격지원이 원본에 접근하거나 Furive 운영 서버·제3자에게 전송하는 배포로 바뀌면 SEC-08 검토를 다시 열고 실제 접근권한·계약·운영 형태에 맞춰 개인정보 처리 역할을 판단합니다.

    원본 dataset의 암호화, 법적 보존 중지와 안전한 파기 증적은 각 데이터 package와 고객 운영 환경이 소유합니다. 저장소의 기본값만으로 완료됐다고 주장하지 않습니다.

    현재 알려진 우선 한계¶

    • 실제 offline release root, 보호된 signing 환경과 fleet key 교체 증적은 저장소만으로 확인할 수 없습니다.
    • main/edge와 여러 native package가 공유 runtime 계정과 Docker 권한을 사용하므로 package별 완전 격리가 아닙니다.
    • 원본 rosbag·영상·센서 dataset은 application-level 저장 암호화를 기본 강제하지 않습니다.
    • integration-gateway의 loopback 연결은 차량 밖 접근을 막지만 같은 PC의 process identity를 인증하지 않습니다. HMI/DLS legacy adapter도 이 경계를 사용하며, 고객용 HMI binary가 검토한 source와 일치하는지는 release 과정에서 별도로 확인해야 합니다.
    • component/image identity 증적은 image 내부 모든 OS·language dependency와 license 판정을 대신하지 않습니다.
    • 실제 repository ruleset, reviewer, secret scanning과 운영 접근 기록은 별도 조직 증적입니다.

    세부 공격 경로와 당시 조치는 2026-08-10 적대적 검토, release workflow와 서명 운영은 CI/CD 기준이 소유합니다. 이 문서에 날짜별 조사 기록을 복사하지 않습니다.

    단일 소유자¶

    경계 소유자
    원격 장비 신원·메시지 검증 core/control_security.py
    package credential·권한 전달 core/package_manager.py
    같은 PC의 package 요청·응답·이벤트 전달 integration-gateway
    데이터 수집·보유·삭제 해당 데이터 package
    OTA 정책·목표·준비·적용·복구 기술 구조의 하나의 OTA 흐름
    고객 데이터의 법적·계약 승인 고객 배포 승인 기록

    Dashboard는 상태와 입력을 전달할 뿐 위 정책의 별도 소유자가 아닙니다.

    검증과 신고¶

    공통 코드 계약은 다음 한 명령으로 확인합니다.

    furive check

    실제 차량에서는 바뀐 경계만 별도로 확인합니다. 설치·systemd·Docker·장치·network를 실제로 실행하지 않았다면 검증 기록에 그 사실을 남깁니다.

    취약점, credential 노출이나 위치·영상 유출 가능성은 공개 issue에 재현 정보를 올리지 않고 보안 정책에 따라 비공개로 신고합니다.
