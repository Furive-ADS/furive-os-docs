    🚀 차량 업데이트¶

    이 문서는 차량 한 대에서 test를 확인하고 복구한 뒤, 같은 변경을 normal 공용판으로 승격하는 실제 흐름을 설명합니다. 명령은 Furive OS 개발 저장소에서 실행하고, 차량에서는 자동으로 열린 운영 화면을 사용합니다.

    vehicle, release, bundle 명령은 개발 저장소에서만 실행하며 차량 배포 저장소를 직접 수정하지 않습니다.

    flowchart LR
  Check["🔎 변경 검사"] --> Test["🚘 한 차량 test"]
  Test --> Verify{"기능·실패·복구 확인"}
  Verify -->|통과| Normal["✅ normal 발행"]
  Verify -->|수정 필요| Check

    활용 팁

    한 차량 test → 기능·복구 확인 → normal. 문서만 바뀌었다면 차량 release나 설치 bundle을 발행하지 않습니다.

    먼저 배포 버전과 설치 묶음을 구분하기¶

    두 산출물의 역할은 다릅니다.

    바뀐 것 필요한 작업
    차량이 실행할 코드·패키지·Docker 이미지·Autoware 버전 배포 버전(release)
    같은 배포 버전에 더할 접근 정보·지도·전달 파일 설치 묶음(bundle)
    두 종류가 모두 바뀜 release 성공 후 bundle
    문서·테스트·CI 편의만 바뀌고 두 산출물이 같음 둘 다 만들지 않음

    release는 서명 후 내용을 바꿀 수 없는 차량 배포 버전입니다. bundle은 이미 발행된 배포 버전에 접근 정보와 지도 같은 설치 파일을 더한 ZIP입니다. 설치 묶음이 패키지, 플랫폼, Autoware 버전이나 계속 유지할 실행 설정을 새로 결정하지는 않습니다.

    판단이 애매하면 CI/CD 릴리즈 판단의 네 질문을 사용합니다. furive release ... --run은 차량 실행 내용이 그대로면 발행을 거부하고, furive bundle은 아직 배포 버전으로 만들지 않은 실행 변경이 있으면 기존 버전 재사용을 거부합니다.

    1. 시험 차량 확인하기¶

    차량은 처음 등록할 때만 플랫폼이 필요합니다.

    ./furive vehicle set lotte-ohmio-1 \
  --platform lotte-ohmio --update normal --version latest
./furive vehicle show lotte-ohmio-1

    이미 등록된 차량은 vehicle show에서 플랫폼, main/edge 패키지, main 화면과 지도를 확인합니다. 정확한 배포 버전에 머물러야 하는 예외에만 --version vYYYY.MM.DD.N을 사용하고, 일반 경로는 latest입니다.

    vehicle set은 개발 저장소의 차량 배정만 바꿉니다. 이미 설치된 차량의 업데이트 종류나 버전을 원격으로 즉시 바꾸지 않습니다. 설치 상태를 바꾸려면 새 배정으로 만든 설치 묶음을 해당 차량에 적용해야 합니다.

    시험 전에는 현재 normal 버전과 바꾼 기능의 정상 결과를 기록합니다.

    2. 한 차량에 test 발행하기¶

    먼저 변경 범위의 테스트와 공통 검사를 통과시킵니다.

    ./furive check

    차량에서 실행·설치할 내용이 바뀌었다면 시험 차량을 test로 바꾸고 발행 계획을 봅니다.

    ./furive vehicle set lotte-ohmio-1 --update test
./furive release test lotte-ohmio-1 --date 2026-08-31 --number 1

    계획에서 차량 ID, 플랫폼, 소스 코드와 변경 결과를 확인한 뒤 같은 명령에 --run을 붙입니다.

    ./furive release test lotte-ohmio-1 --date 2026-08-31 --number 1 --run

    서명된 test 배포 버전 발행이 성공한 뒤 시험 차량 설치 묶음을 만듭니다.

    ./furive bundle lotte-ohmio-1

    사용 설명서도 함께 전달할 때만 --include-manual을 붙입니다. 내부 개발 PC용 ./furive bundle development에는 설명서가 기본으로 들어갑니다.

    생성된 차량 묶음 하나를 정비 시간에 각 PC에서 ./bootstrap.sh로 적용합니다. 신규 PC만 장비를 선택하고 기존 설치는 저장된 배정을 유지합니다. 설치 흐름은 차량 PC 설치를 따릅니다.

    접근 정보, 지도 또는 기존 배포 버전 선택처럼 설치 묶음만 바뀌었다면 새 배포 버전을 만들지 않습니다. 기존 서명 버전을 유지한 새 설치 묶음을 만들고 한 차량에서 전달 결과만 확인합니다.

    3. 차량에서 기능과 복구 확인하기¶

    main 운영 화면은 로그인 뒤 자동으로 열립니다. 업데이트를 준비·적용한 뒤 다음을 실제 결과로 확인합니다.

    • 화면에 표시된 목표 버전과 실행 중인 버전이 일치한다.
    • 바꾼 기능의 정상 입력이 기대한 ROS·API·파일·화면·장치 결과를 만든다.
    • 대표 실패 입력이 정한 실패 상태를 만든다.
    • main과 edge의 필수 프로그램이 정상 상태를 회복한다.
    • 재시작 뒤에도 같은 결과가 유지된다.

    프로세스나 container가 살아 있다는 사실만으로 기능 PASS를 기록하지 않습니다. 문제가 있을 때만 터미널에서 다음 순서로 확인합니다.

    furive status
furive service logs

    운영 화면을 닫았을 때만 furive dashboard로 다시 엽니다.

    시험이 끝나면 운영 화면의 이전 정상 버전 복구를 적용합니다. 새 버전은 현재 버전과 떨어진 곳에 준비되고, 다음 시작에서 전환됩니다. 필수 프로그램이 안정된 정상 상태가 되지 않으면 Furive가 업데이트 직전 전체 배포 버전으로 자동 복구합니다.

    복구 뒤에는 다음을 다시 확인합니다.

    • 버전이 시험 전 normal로 돌아왔다.
    • 핵심 기능과 main-edge 연결이 정상이다.
    • 실패한 test가 자동으로 다시 적용되지 않는다.

    내부 준비 폴더와 변경 기록을 조사할 때만 이전 정상 버전 복구 기준과 업데이트 호환 정책을 봅니다.

    4. 확인한 변경만 normal로 승격하기¶

    차량 시험을 마친 코드를 공용 개발 저장소에 반영한 뒤 차량 배정을 normal로 되돌리고 발행 계획을 확인합니다.

    ./furive vehicle set lotte-ohmio-1 --update normal --version latest
./furive release normal --date 2026-08-31 --number 2

    계획에서 시험을 통과한 플랫폼만 새 승인판으로 이동하고, 시험하지 않은 플랫폼은 이전 승인판을 유지하는지 확인합니다. 맞으면 발행합니다.

    ./furive release normal --date 2026-08-31 --number 2 --run

    이미 normal latest로 설치된 일반 차량은 새 공용판을 원격으로 찾으므로 배포 버전마다 설치 묶음을 다시 설치하지 않습니다. 시험 차량에는 test 설치 묶음이 전달한 차량 배정과 시험용 접근 정보가 남을 수 있으므로, normal 운영으로 돌릴 때는 공용판 발행 뒤 새 설치 묶음을 만들어 적용합니다.

    ./furive bundle lotte-ohmio-1

    한 번 발행한 버전 번호를 다른 소스 코드에 다시 사용하지 않습니다. normal 적용 뒤 운영 화면 또는 furive status에서 목표 버전과 프로그램 상태를 확인합니다.

    완료 조건¶

    • 변경 범위 테스트와 furive check가 통과했다.
    • 한 차량의 test에서 정상·대표 실패 결과를 확인했다.
    • 시험 전 normal로 복구해 기능을 다시 확인했다.
    • 배포 버전과 설치 묶음을 실제 변경 내용으로 구분했다.
    • 시험한 플랫폼만 normal 새 승인판으로 이동했다.
    • test 차량의 설치 상태도 normal bundle로 되돌렸다.

    단계별 확인 절차는 변경 검증, 배포 버전 발행과 보존 세부사항은 CI/CD 기준을 봅니다.
