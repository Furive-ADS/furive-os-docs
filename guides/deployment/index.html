    📦 차량 PC 설치¶

    이 문서는 furive-os-install-*.zip을 전달받은 설치자가 차량 PC 한 대를 준비하는 순서입니다. 소스 코드 저장소를 개발하는 절차는 Furive OS 개발 시작에 따로 있습니다.

    대상 차량 설치 담당자

    시작 위치 설치 ZIP을 푼 폴더

    완료 기준 설치 완료·서비스 자동 시작

    활용 팁

    압축 해제 → ./bootstrap.sh → 설치 완료 확인. 신규 PC만 장비를 한 번 선택하며, 기존 설치는 저장된 배정을 유지합니다.

    설치 전에 받은 것¶

    PC 한 대로도 설치해 사용할 수 있습니다. 한 PC에서 자율주행·운영과 HMI·로깅 등을 함께 쓸 때는 그 기능이 포함된 1PC용 배정을 받습니다. A-ECU·HMI-ECU 분산 구성은 부하를 나누는 권장 방식입니다.

    받은 구성 설치 순서와 완료 확인
    1PC 한 PC에서 A-ECU를 선택해 한 번 설치하고, 함께 배정된 패키지가 실행되는지 확인
    A-ECU·HMI-ECU 분산 각 PC에서 같은 ZIP을 사용해 해당 장비를 선택하고, 설치 뒤 PC 연결과 기능을 확인

    현재 차량용 기본 배정에서 A-ECU만 설치하면 A-ECU의 기능부터 사용할 수 있습니다. HMI·DLS를 함께 실행하려면 해당 패키지를 포함한 구성이 필요합니다. 같은 PC에 두 장비의 설치를 덧씌우지 않습니다. 구성 차이는 1PC와 분산 구성을 봅니다.

    차량용 ZIP 하나를 설치할 PC에서 사용합니다. 신규 설치에서는 장비 라벨을 확인하고 PC를 선택합니다. A-ECU(자율주행·운영 대시보드)가 기본 선택이며, HMI-ECU(데이터 로깅·부가 기능)는 해당 PC에서 선택을 바꿉니다. 기존 설치는 저장된 PC 배정을 사용합니다. 차량·플랫폼·버전은 다시 묻지 않습니다.

    단일 묶음은 새 PC 설치 계약을 포함한 배포 버전부터 생성할 수 있습니다. 이전 버전에서 받은 장비별 ZIP은 지정된 PC 전용이며, 선택 화면 없이 기존 방식으로 설치됩니다.

    같은 이름의 Docker 실행 이미지 파일을 함께 받았다면 ZIP과 같은 폴더에 둡니다. 설치 파일에는 차량 접근 정보가 들어 있으므로 Git, 공개 메신저나 공용 드라이브에 올리지 않습니다.

    설치 묶음의 파일·폴더 자세히 보기

    설치 묶음에 들어 있는 것¶

    파일·폴더 하는 일
    bootstrap.sh 묶음을 검사하고, 지정된 배포 버전을 설치한 뒤 서비스를 시작하는 유일한 실행 파일
    README.txt 이 묶음의 차량·PC 역할·버전과 설치 순서를 사람이 읽기 쉽게 요약
    bundle.env, manifest.yaml 차량, 플랫폼, normal/test, 배포 버전과 포함 항목을 고정한 설치 정보. 직접 수정하지 않음
    keys/, autoware-keys/, public-keys/, github-known-hosts 배포·Autoware 저장소에 안전하게 접근하고 접속 대상을 확인하는 키
    node-identities/, release-trust/ PC별 인증 자료와 배포 서명 확인 자료. 선택한 PC의 개인키만 운영 경로에 설치
    installation-policy.py 서명된 배포 버전에서 가져온 PC 선택·기존 설치 확인 코드. 직접 실행하거나 수정하지 않음
    map-assets/ 해당 플랫폼에 필요한 지도 파일. A-ECU에서만 적용
    registry.env Furive 패키지 이미지와 OTA Update를 받는 Harbor pull 인증정보. 현재 차량 설치 묶음에는 항상 포함
    source-keys/, development-git/ Source Unlock 또는 차량 test 개발 접근이 필요할 때만 포함되는 보호 정보
    Furive-OS-사용설명서.pdf 내부 개발 묶음처럼 설명서 포함을 선택했을 때만 들어가는 사용 설명서
    reset-clean-install.sh 설치 재현 시험용 되돌림 도구. 소유권 기록이 있는 Furive 설치 항목만 제거

    묶음에는 A-ECU용 docker-images/seed.env가 들어갈 수 있습니다. 이 파일이 가리키는 큰 Autoware Docker 이미지 .tar는 ZIP 안이 아니라 ZIP과 같은 폴더에 별도로 전달됩니다. 이 seed는 Harbor 접근 자체를 대체하지 않습니다. 패키지·플랫폼·Autoware 버전 자체는 묶음이 새로 정하지 않고, 묶음에 고정된 서명 배포 버전에서 가져옵니다.

    단일 묶음에는 두 PC의 인증 자료가 있으므로 설치 담당자가 안전하게 관리합니다. PC 선택은 설치 대상을 정하는 절차이며 묶음 안의 다른 개인키에 대한 접근을 차단하지 않습니다.

    설치¶

    flowchart LR
  Zip["📦 ZIP 압축 해제"] --> Bootstrap["⌨️ ./bootstrap.sh"]
  Bootstrap --> Role{"기존 설치인가?"}
  Role -->|아니요| Select["장비 한 번 선택"]
  Role -->|예| Keep["저장된 배정 유지"]
  Select --> Install["설치 계획 확인·설치"]
  Keep --> Install
  Install --> Done["✅ 서비스 자동 시작"]

    ZIP을 압축 해제하고 만들어진 설치 폴더에서 bootstrap.sh만 실행합니다.

    ./bootstrap.sh

    신규 PC에서는 A-ECU가 기본 선택되어 있습니다. 위·아래 방향키로 이동하고 Enter로 확정합니다. 장비 선택을 완료하지 못하면 설치하지 않습니다. 이미 HMI-ECU로 설치한 PC를 다시 실행해도 A-ECU 기본값으로 바뀌지 않습니다. 기록이 충돌하면 기존 배정을 확인한 뒤 다시 진행합니다.

    필요한 sudo 비밀번호는 설치 중 한 번 물을 수 있지만 저장하지 않습니다. 설치기는 이 PC에 맞는 Furive 배포 버전과 패키지를 준비하고 서비스를 시작합니다.

    설치기가 판단하고 이어서 실행하는 전체 구조는 bootstrap 설치 흐름에 짧게 정리되어 있습니다.

    스크립트는 변경 전에 설치·유지·건너뜀 항목과 정확한 Autoware image, NVIDIA driver package, 재부팅 여부를 보여주고 y/N을 한 번만 받습니다. 설치 중에도 현재 작업과 이유가 진행률 옆에 계속 표시됩니다. 기준을 만족하는 기존 driver는 유지합니다. 승인 뒤 image나 driver 후보가 달라지면 다른 대상을 임의로 설치하지 않고 중단합니다.

    Furive가 NVIDIA driver를 설치할 때는 host package, NVIDIA Toolkit, credential, Autoware 사용자 도구, 자동 실행과 서비스 등록을 먼저 끝냅니다. driver 설치는 재부팅 직전의 마지막 큰 작업이며, 그 뒤 Toolkit이나 Docker 설정을 다시 실행하지 않습니다. 10초 카운트다운 후 자동으로 재부팅합니다. Ctrl+C를 누르면 자동 재부팅만 취소되며 편한 시간에 직접 재부팅할 수 있습니다.

    다음 부팅에서는 일회성 작업이 로그인 세션과 sudo 인증 없이 지정된 Furive 사용자로 실행됩니다. furive_autoware_main clone, 하위 source vcs import, Furive Autoware container build와 colcon build를 완료한 뒤에만 Furive 서비스를 시작합니다. 로그인하면 최대화 터미널이 재부팅 전과 같은 진행률 형식으로 이를 보여줍니다. root로 Autoware source를 실행하지 않고, sudoers나 비밀번호, 자동 로그인 설정을 저장·변경하지 않습니다. 실패하면 Furive 서비스 시작을 막고 원인을 기록합니다.

    완료 메시지가 나오면 설치는 끝입니다.

    설치 뒤 자동으로 되는 일¶

    • 설치한 PC의 서비스는 이미 시작되어 있고 이후 부팅 때 자동으로 실행됩니다.
    • A-ECU의 운영 화면은 보통 데스크톱 로그인 후 자동으로 열립니다. 내부 개발 PC는 필요할 때 furive dashboard로 엽니다.
    • HMI-ECU의 배정된 패키지는 자동으로 동작합니다. 구체적인 화면 실행은 플랫폼 설정을 따릅니다.
    • PC 배정은 설치 상태가 유지하고 차량·플랫폼·업데이트는 검증된 배포 설정을 사용합니다.

    따라서 정상 설치 뒤 furive dev나 별도 시작 명령을 실행하지 않습니다. 내부 개발 PC처럼 화면 자동 열기가 꺼진 경우에만 furive dashboard를 사용합니다.

    설치 뒤 지도·운용 설정, 상태 확인, 로그와 안전한 재시작은 Furive OS 기본 사용법에 이어집니다.

    문제가 있을 때¶

    설치 도중 실패했다면 출력의 첫 오류를 해결하고 같은 ./bootstrap.sh를 다시 실행합니다. 완료한 단계는 재사용하므로 다른 설치 명령으로 바꾸지 않습니다. 설치 기록이 남기 전에 중단된 경우에는 같은 장비를 다시 선택합니다.

    설치는 끝났지만 동작을 확인해야 할 때만 다음 순서로 봅니다.

    furive status
furive service logs

    A-ECU 운영 화면을 닫았거나 로그인 자동 시작에 실패한 경우에만 다시 엽니다.

    furive dashboard

    부팅 시 서비스와 로그인 시 화면 자동 열기는 설치 뒤에도 바꿀 수 있습니다. 주요 패키지 설정과 함께 Furive OS 기본 사용법에 정리되어 있습니다.

    새 묶음으로 복구한 직후 furive setup --repair를 이어서 실행하지 않습니다. 업데이트나 설치 상태를 믿을 수 없다면 설치 담당자에게 새로 전달받은 묶음의 ./bootstrap.sh부터 다시 사용합니다.

    설치 파일 정리¶

    설치와 현장 확인이 끝나면 승인된 보관본을 제외한 ZIP, 별도 Docker 이미지 파일과 압축 해제본을 삭제합니다. 실행 중인 Furive 배포 버전은 별도 설치 위치에 있으므로 전달 파일을 계속 둘 필요가 없습니다.

    설치 묶음을 만드는 배포 담당자는 차량 업데이트를 사용합니다. PC에 남는 도구, 서비스와 접근 정보의 정확한 목록이 필요할 때만 호스트 영향을 확인합니다.
