    ⌨️ CLI 명령어 표¶

    하고 싶은 작업으로 명령을 찾으세요. 상태 조회부터 패키지·Autoware·업데이트·토픽 녹화까지, 실행 범위와 적용 조건을 함께 정리했습니다.

    furive help       # 이 PC에서 가능한 작업부터 확인
furive status     # 전체 운용 상태와 문제 확인

    설치된 PC에서는 furive, source 저장소 루트에서는 ./furive를 사용합니다. <name> 같은 표시는 실제 값으로 바꿉니다. 이 표는 필요한 명령을 고르는 참고 자료입니다.

    먼저 찾는 명령¶

    하고 싶은 일 명령 확인할 결과
    이 PC에서 사용할 수 있는 기능 찾기 furive help 장비 이름, 사용 가능 여부, 먼저 시작할 패키지
    전체 운용 상태 확인 furive status 정상·확인 필요·이상·확인 불가와 문제 목록
    패키지 상태 확인 furive package status 이 PC에서 관리하는 패키지별 상태
    패키지 로그 확인 furive package logs <name> 해당 패키지의 최근 로그
    서비스 로그 계속 보기 furive service logs 최근 로그와 이후에 추가되는 로그
    중단된 재부팅 후 설치 이어가기 furive setup --resume 저장된 설치를 재개하고 진행 화면 표시
    닫은 운영 화면 다시 열기 furive dashboard 설치된 플랫폼의 운영 화면
    Autoware 상태 확인 furive autoware status 런처와 Autoware 실행 상태
    업데이트 상태 확인 furive ota status 준비·적용 상태와 업데이트 허용 정책
    PC 자원·네트워크 확인 furive system status CPU·메모리·디스크·네트워크와 현재 설정
    차량 토픽과 전달 상태 확인 furive topic list 발행·전달 설정·수신 PC 조회 상태

    <name>, <topic>, <version> 같은 표시는 실제 값으로 바꿉니다. 예를 들어 설치된 DLS의 로그는 furive package logs data-logging-system으로 봅니다. 표 전체를 위에서부터 실행하는 절차는 아닙니다.

    도움말과 실행 조건¶

    참고

    현재 source에 구현된 CLI 기준입니다. 설치 버전과 선택된 패키지에 따라 기능이 다릅니다. furive help에서 지원 여부를 확인하세요. 문서 갱신만으로 차량 소프트웨어가 업데이트되지는 않습니다. PC 배정은 설치 상태에서 읽으므로 일반 운용 명령에 장비 이름이나 main/edge를 다시 넣지 않습니다.

    명령 용도
    furive 인자 없이 실행하면 현재 PC에 맞는 도움말 표시
    furive help 설치된 패키지·실행 상태와 연결된 PC의 사용 가능 기능 안내
    furive help --json 같은 안내를 JSON으로 출력
    furive --help 이 버전이 지원하는 전체 명령 문법
    furive ota --help 특정 명령 묶음의 사용법; ota 대신 필요한 이름 사용
    furive package logs --help 개별 작업의 인자와 옵션

    운영 명령은 실행 중인 Furive 서비스에 연결합니다. 창을 닫아도 서비스가 동작하면 CLI를 사용할 수 있습니다. 서비스 시작 필요이면 설치된 PC에서 furive service start, 패키지 시작 필요이면 도움말에 표시된 furive package start <name>을 사용합니다. 기능이 목록에 없으면 설치 구성과 버전을 확인합니다. 미설치 source 개발은 개발 시작을 따릅니다.

    화면과 CLI는 같은 패키지 관리자·OTA·Launcher·시스템 기능을 호출합니다. 명령이 접수됐다는 응답만으로 빌드·업데이트가 끝난 것은 아니므로 해당 status와 로그에서 완료를 확인합니다.

    서비스와 운영 화면¶

    재부팅 후 설치가 중단됐다면 로그의 원인을 해결한 뒤 furive setup --resume를 실행합니다. 데스크톱에서는 설치 진행 터미널을 다시 열고, 화면이 없는 접속에서는 현재 터미널에 진행을 표시합니다. 이미 진행 중이면 같은 작업을 보여주며, 완료된 설치는 다시 실행하지 않습니다. 설치 완료 후 서비스 시작은 저장된 자동 시작 설정을 따릅니다. 미완료 설치가 있는 PC의 service start·service restart도 이 재개 흐름을 사용합니다.

    명령 하는 일 실행 범위·확인 사항
    furive status 전체 운용 문제와 서비스·버전·Autoware 상태 요약 전체 문제 집계는 A-ECU가 담당; 최신 집계를 받지 못하면 확인 불가
    furive status --json 상태를 JSON으로 출력 전체 운용 집계는 operation 항목
    furive service start 설치된 서비스 시작 이 PC의 저장된 배정 사용
    furive service stop 서비스와 그 서비스가 관리하는 패키지 중지 정비 상태에서 실행
    furive service restart 설치된 서비스 재시작 실행·기록·업데이트에 미치는 영향 확인
    furive service logs 최근 100줄부터 새 서비스 로그까지 계속 표시 Ctrl+C는 로그 보기만 종료
    furive service logs --lines 200 --no-follow 최근 200줄을 출력하고 종료 자동화·오류 공유용
    furive dashboard 닫은 기본 운영 화면 다시 열기 정상 설치 후 매번 실행할 필요 없음
    furive dashboard --web 전체 운영 화면을 브라우저로 열기 패키지·PC별 상태 조사
    furive dashboard --print-only 운영 화면 주소만 출력 화면을 직접 열지 않음
    furive dashboard --package <name> 해당 패키지 화면을 별도 창으로 열기 화면을 제공하는 패키지에 사용

    패키지¶

    명령 하는 일 실행 범위·확인 사항
    furive package list 발견된 패키지 목록 조회 정확한 패키지 이름 확인
    furive package status 이 PC 패키지의 실행 상태 조회 차량 전체 집계는 furive status
    furive package status <name> 패키지 하나의 상태 조회 필요한 경우 연결된 PC의 해당 패키지에 전달
    furive package start <name> 운영 중인 관리자를 통해 패키지 시작 서비스가 실행 중인 일반 운용 경로
    furive package stop <name> 패키지 중지 그 패키지의 기록·센서·차량 기능에 영향
    furive package restart <name> 패키지 재시작 재시작 후 상태와 로그 확인
    furive package logs <name> --lines 200 최근 패키지 로그 200줄 조회 기본 100줄, 최대 1,000줄; 계속 따라가지 않음
    furive package run <name> 패키지와 필수 의존성을 전경 실행 서비스가 중지된 환경에서 사용; Ctrl+C로 종료

    꼭 확인

    일반 운용은 start, 서비스가 중지된 환경의 전경 실행은 run입니다. 전체 서비스가 실행 중이면 furive package start <name>을 사용합니다.

    이름을 지정한 명령은 로컬 설치 위치를 먼저 확인합니다. 연결된 다른 PC로 전달해야 하는 경우 두 PC가 같은 운용 제어 기능을 지원해야 하며, 대상이 불명확하면 중단합니다. 현재 A-ECU에서 원격 패키지를 제어하는 경로는 연결된 대상 PC 한 대를 전제로 합니다.

    설치된 deploy에서는 package add, package check를 제공하지 않습니다. 독립 저장소를 연결하는 명령은 source 개발과 배포에 있습니다. 화면에서 같은 작업을 하려면 Package Manager를 봅니다.

    OTA 업데이트¶

    주의

    적용·복구·재시작은 정비 상태에서 실행합니다. 요청이 접수된 뒤에도 furive ota status에서 실제 전환 결과를 확인하세요. disable 잠금은 수동 적용과 복구에도 영향을 줍니다.

    명령 하는 일 확인 사항
    furive ota status OTA 상태와 업데이트 정책 조회 업데이트 잠금과 Autoware 포함 여부도 확인
    furive ota enable 자동 업데이트 잠금 해제 허용된 업데이트 흐름 재개
    furive ota disable 업데이트 잠금 설정 수동 적용·복구도 잠금 정책의 영향을 받음
    furive ota check 지정된 업데이트 경로에서 새 버전 확인 확인과 적용은 별개
    furive ota prepare 새 버전을 별도 공간에 준비 다운로드·준비 결과를 status로 확인
    furive ota apply 준비한 업데이트 적용 요청 정비 상태에서 실행; 상태 확인 후 필요할 때 재시작
    furive ota history 업데이트·복구 이력 조회 복구할 실제 버전 또는 revision 확인
    furive ota rollback <version> 검증된 이전 버전으로 복구 요청 history에 표시된 대상 사용
    furive ota restart 업데이트 적용을 위한 운영 서비스 재시작 status가 재시작 대기일 때 사용

    이 PC의 OTA 기능을 사용하므로 해당 패키지와 서비스가 준비되어 있어야 합니다. apply나 rollback 뒤에는 furive ota status로 실제 전환 결과를 확인합니다. 업데이트 정책과 화면 절차는 OTA Updater, 새 버전 발행은 차량 업데이트를 봅니다.

    Autoware¶

    명령 하는 일 확인 사항
    furive autoware status Launcher와 Autoware 상태 조회 실행·빌드·지도와 현재 설정 확인
    furive autoware start 저장된 설정으로 Autoware 시작 지도·차량·센서 모델을 먼저 확인
    furive autoware stop Autoware 중지 차량을 정비 상태로 만든 뒤 실행
    furive autoware restart 중지 후 다시 시작 완료는 status에서 확인
    furive autoware config 현재 실행 설정 조회 조회만 수행
    furive autoware config --file <file> YAML/JSON 파일로 설정 변경 Launcher 화면과 같은 설정 필드 사용
    furive autoware build 현재 설정으로 빌드 시작 세부 요청은 --file <file>로 전달 가능
    furive autoware cancel-build 진행 중인 빌드 취소 요청 취소 결과와 로그 확인
    furive autoware sync 설정된 Autoware 소스 동기화 세부 요청은 --file <file>로 전달; 개발 변경을 먼저 보존
    furive autoware open map 지도 폴더 열기 그래픽 세션이 있는 PC에서 사용
    furive autoware open source 소스 폴더 열기 실제 폴더는 Launcher가 실행되는 PC에 있음
    furive autoware open source_vscode 소스를 VS Code로 열기 VS Code와 그래픽 세션 필요
    furive autoware update status OTA의 Autoware 업데이트 포함 정책 조회 Furive 전체 업데이트 정책과 별개
    furive autoware update enable Autoware 업데이트 포함 허용 다음 OTA 흐름부터 정책 적용
    furive autoware update disable Autoware 업데이트 포함 차단 현재 Autoware를 중지하는 명령은 아님

    open은 launch_mode, vehicle, sensor_kit 폴더도 선택할 수 있습니다. --file은 객체 형태의 YAML/JSON을 읽으며, config 조회 결과를 그대로 재입력하는 것과 빌드·동기화 요청 형식은 구분합니다. 설정과 각 작업의 의미는 Launcher를 따릅니다.

    HMI-ECU에서 실행한 Autoware 명령은 연결된 A-ECU의 Launcher로 전달됩니다. open도 Launcher가 있는 PC에서 폴더를 엽니다. 두 PC의 연결과 호환되는 운용 제어 기능이 필요합니다.

    시스템¶

    명령 하는 일 확인 사항
    furive system status PC 자원·디스크·네트워크·오디오와 설정 조회 명령을 실행한 PC 기준
    furive system ros-domain <domain-id> ROS Domain ID 변경과 관련 패키지 재시작 요청 0~231; 232는 내부 전달용이라 사용 불가
    furive system remote-access status 원격접속 허용 상태 조회 접속 ID 표시는 패키지·PC의 공개 정책에 따름
    furive system remote-access enable 원격접속 허용 이 PC의 원격접속 기능 제어
    furive system remote-access disable 원격접속 차단 진행 중인 원격 접속도 끊길 수 있음
    furive system audio status 오디오 상태 조회 이 PC 기준
    furive system audio mute 음소거 이 PC 기준
    furive system audio unmute 음소거 해제 이 PC 기준
    furive system poweroff --confirm PC 전원 종료 요청 정비 상태 확인 후 명시적으로 실행; 전체 차량 종료 명령이 아님

    A-ECU의 ROS Domain 변경은 기존 시스템 설정 경로를 통해 연결된 PC에도 전달됩니다. HMI-ECU에서 실행하면 해당 PC의 설정을 바꿉니다. 패키지·컨테이너 재시작 요청이 접수된 뒤에는 수신 상태까지 확인합니다. 화면 절차는 System Manager를 봅니다.

    토픽과 DLS 녹화¶

    명령 하는 일 확인 사항
    furive topic list 중앙 설정 토픽의 타입·전달·수신 상태 조회 평소 확인용
    furive topic list --all 차량에서 발행 중인 미등록·미수신 토픽까지 조회 조회만으로 전달이나 녹화를 시작하지 않음
    furive topic add <topic> 발행 중인 토픽의 타입을 읽고 중앙 전달 설정에 추가 실행·녹화 중에는 저장 후 적용 대기; 정비 상태에서는 바로 적용
    furive topic remove <topic> 개별 토픽 전달 설정 제거 실행·녹화 중에는 적용 대기; 다른 소비자의 수신 영향 확인
    furive topic apply 저장된 중앙 전달 설정을 양쪽 PC에 적용 적용 대기일 때 정비 상태에서 실행; 이미 적용됐으면 반복할 필요 없음
    furive topic record <topic> 기존 DLS 기록 선택에 토픽을 추가하고 수동 녹화 시작 중앙 전달 허용과 DLS에서의 조회 가능 여부를 먼저 확인
    furive topic sessions DLS 세션 이름·로컬/NAS 위치·크기 조회 검사할 로컬 세션 이름 확인
    furive topic inspect <세션> 실제 녹화 파일 전체 검사 접수 접수는 완료가 아님. 녹화 중이면 종료 후 검사
    furive topic inspect <세션> --status 저장된 결과·진행 상태 조회 새 검사를 시작하지 않음. --bag <경로>로 상세 bag 선택
    furive topic inspect <세션> --cancel 진행·대기 중 검사 취소 요청 --status에서 실제 취소 완료 확인
    furive topic stop DLS 녹화 중지 토픽 하나의 전달을 끊는 명령이 아니라 진행 중인 녹화 종료

    현재 토픽 변경과 녹화·세션·파일 검사 요청은 A-ECU와 연결된 수신 PC 한 대를 전제로 합니다. HMI-ECU에서 입력한 토픽 명령도 A-ECU의 중앙 관리 경로로 전달합니다. 양쪽 통신 패키지와 DLS가 필요한 기능을 지원해야 합니다. 1PC에 함께 배정한 DLS는 로컬 DLS 화면에서 녹화·세션·검사를 사용합니다. 이 CLI 경로가 로컬 DLS로 자동 전환되지는 않습니다. PC 구성별 범위를 확인하세요.

    꼭 확인

    설정 저장 · 전달 적용 · 토픽 발견 · 파일 저장은 서로 다른 상태입니다. add는 발행 중에 타입을 읽어 저장할 수 있습니다. 적용 대기라면 정비 시 Autoware와 녹화를 중지하고 apply를 실행한 뒤, 필요한 발행 프로그램을 다시 시작해 수신을 확인합니다.

    메시지 타입 미설치·구버전 통신 패키지·여러 타입 충돌·플랫폼 제외 토픽은 이유와 함께 거부합니다. 실행 중인 Autoware나 DLS 녹화를 강제로 끊으며 전달 경로를 바꾸지는 않습니다. 부분 적용에 실패하면 응답에서 기존 설정 복구 여부를 확인합니다.

    record는 기존에 선택한 기록 토픽도 유지합니다. 이미 녹화 중이면 먼저 topic stop으로 마칩니다. 목록에서 조회된다는 것과 실제 메시지가 파일에 저장된다는 것은 다르므로, 녹화 후 DLS 세션에서 메시지 수와 파일 크기를 확인합니다. 차량 명령용 역방향·양방향 경로는 이 명령으로 변경하지 않습니다. 녹화는 NAS 전송을 자동 허용하지 않습니다. 세션·재생·전송은 DLS 가이드를 봅니다.

    녹화 파일 검사는 다음 순서로 요청합니다. 세션 이름은 목록에 표시된 값을 사용합니다.

    furive topic sessions
furive topic inspect 2026-09-11
furive topic inspect 2026-09-11 --status

    주기를 아는 토픽은 --expected-hz /토픽=Hz를 반복해 지정할 수 있습니다. 0은 이벤트 토픽입니다. 기대 Hz를 생략해도 저장소 무결성·전체 메시지 읽기·메시지 수·시간 간격을 검사합니다.

    furive topic inspect 2026-09-11 --expected-hz /sensing/camera/camera_top/image_raw=10 --expected-hz /tf_static=0
furive topic inspect 2026-09-11 --status --bag bags/2026-09-11-10-00-00 --json
furive topic inspect 2026-09-11 --cancel

    --status는 bag별 상태와 선택한 bag의 실제/메타데이터 메시지 수, 평균 Hz, 기대 대비 부족, 최대 시간 간격과 발생 위치를 보여줍니다. --json은 같은 DLS 결과를 자동화에 전달합니다. 조회 명령 성공은 검사 통과를 뜻하지 않습니다. bags[].state와 bags[].result, selected.report를 확인합니다. 전체 검사 범위·미검증 항목은 녹화 검사 안내를 따릅니다.

    설치 설정과 제거¶

    차량 최초 설치는 전달받은 묶음의 ./bootstrap.sh로 시작합니다. 신규 단일 묶음에서 PC를 한 번 선택하고, 기존 설치는 저장된 배정을 유지합니다. 자세한 절차는 차량 PC 설치를 봅니다.

    명령 하는 일 확인 사항
    furive setup --repair 설치 설정을 유지하며 현재 설치 복구 새 차량 최초 설치를 대신하는 절차는 아님
    furive setup --autostart on 다음 부팅부터 서비스 자동 시작 켜기 현재 실행 상태는 유지
    furive setup --autostart off 다음 부팅부터 서비스 자동 시작 끄기 지금 중지하려면 service stop
    furive setup --dashboard-autostart on 로그인 시 운영 화면 자동 열기 켜기 화면 자동 시작을 지원하는 PC에 사용
    furive setup --dashboard-autostart off 로그인 시 운영 화면 자동 열기 끄기 이미 열린 창은 유지
    furive remove --dry-run 제거할 항목만 확인 실제 제거 전 범위 확인
    furive remove 설치된 Furive OS 제거 정비 상태에서 실행; 제거 확인 절차 진행

    고급 설치의 플랫폼·버전 선택은 setup --customize 아래에 있습니다. 제거 시 --purge-data, --purge-credentials, --purge-source-keys, --purge-logs, --remove-images는 각각 추가 삭제 범위를 늘리므로 필요한 항목만 선택합니다. --yes는 확인 질문을 생략합니다. 전체 옵션은 해당 명령의 --help, PC에 미치는 영향은 호스트 영향을 확인합니다.

    Source 개발과 배포¶

    다음 명령은 source 저장소 루트에서 실행합니다. 설치된 deploy에는 check, vehicle, release, bundle, package add, package check 같은 source 작업 명령이 없습니다.

    명령 하는 일 다음 확인
    ./furive dev main 미설치 source의 첫 자율주행 PC 개발 실행 종료는 Ctrl+C; edge 개발일 때만 ./furive dev edge
    ./furive dev --no-ui 설치 배정을 사용해 화면 없이 개발 실행 GUI 패키지를 제외하려면 --headless, 브라우저를 쓰려면 --browser; 옵션은 하나만 선택
    ./furive package add <repository-url> 독립 프로그램 저장소 연결 프로그램 연결
    ./furive package run <name> 프로그램과 필수 의존성 전경 실행 상태·로그와 정상 종료
    ./furive package check 연결 규칙과 패키지 자체 테스트 실패 원인 수정
    ./furive check 공통 코드·규칙·패키지·배포 산출물 전체 검사 테스트와 검증 결과
    ./furive check --quick 배포 산출물 검사 생략 나머지 검사는 수행
    ./furive check --platform <platform> 해당 플랫폼의 Autoware 버전 빌드 검사 포함 실제 빌드 환경 필요
    ./furive vehicle list 등록된 차량 목록 조회 --format json 지원
    ./furive vehicle show <vehicle-id> 차량의 플랫폼·업데이트·버전 조회 --format json 지원
    ./furive vehicle set <vehicle-id> --platform <platform> 차량 플랫폼 지정 새 차량 등록에도 사용; 차량에 즉시 적용되지 않음
    ./furive vehicle set <vehicle-id> --update test 한 차량 시험판 선택 normal로 변경하면 공용판; 종류 변경 시 버전은 latest
    ./furive vehicle set <vehicle-id> --version <version> 차량에 적용할 버전 지정 지정된 배포 버전의 존재·검증 필요
    ./furive release test <vehicle-id> --date <date> --number <number> 한 차량 시험판 발행 계획 확인 실제 발행은 --run 추가
    ./furive release normal --date <date> --number <number> 공용판 발행 계획 확인 전체 검증·차량 시험 후 --run 추가
    ./furive bundle <vehicle-id> 기존 서명된 배포 버전으로 차량 설치 묶음 생성 전달 파일과 차량 배정 확인
    ./furive bundle development 내부 개발 PC용 묶음 생성 개발 환경 준비
    ./furive bundle <vehicle-id> --include-manual 설치 묶음에 PDF 사용 설명서 포함 development에는 기본 포함

    <date>는 2026-09-10 같은 YYYY-MM-DD, <number>는 1 이상의 배포 순번입니다. 개발 실행 동안 OTA 임시 보호를 사용하며, 종료하면 기존 상태를 복원합니다. 설치된 PC의 개발 실행은 furive dev로 배정을 재사용합니다. 발행·설치 묶음의 판단은 차량 업데이트를 따릅니다. 문서만 바꾼 경우에는 차량 release나 bundle을 새로 만들지 않습니다.

    JSON과 오류 확인¶

    help, status, 패키지의 status/start/stop/restart/logs, ota, autoware, system, topic 명령은 --json을 지원합니다. vehicle 조회는 별도의 --format json을 사용합니다. 모든 명령에 같은 옵션이 있는 것은 아니므로 자동화 전 해당 --help를 확인합니다.

    메시지·상황 다음 행동
    실행 중인 Furive를 찾지 못함 설치된 PC는 furive service start; 미설치 source는 개발 시작 절차 확인
    패키지 시작 필요 furive help가 안내하는 패키지를 시작한 뒤 상태 재확인
    중앙 PC 연결 확인 필요 furive status, furive service logs에서 PC 연결과 버전 확인
    명령 지원 안 함·통신 패키지 계약 미지원 기능을 포함한 버전으로 해당 PC·패키지 업데이트
    재시작 대기 작업 상태를 확인하고 정비 중에 해당 재시작 명령 실행
    전달 설정됨·수신 대기 발행자와 수신 PC의 타입·연결 확인; 녹화 성공으로 간주하지 않음

    새 명령은 CLI 구현과 기능 소유자의 현재 계약을 기준으로 문서에 반영합니다.
