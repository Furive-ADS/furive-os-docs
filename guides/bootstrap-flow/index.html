    bootstrap 설치 흐름¶

    차량 설치 묶음에서는 다음 명령 하나만 실행합니다.

    ./bootstrap.sh

    단일 묶음의 bootstrap.sh는 신규 PC에서 장비를 한 번 선택합니다. 1번 A-ECU가 기본 선택되어 있으며, 위·아래 방향키로 이동하고 Enter로 확정합니다. 기존 설치가 있으면 그 PC 배정을 유지합니다. 차량·플랫폼·버전은 묻지 않고, 선택한 PC의 구성이 서명된 배포 버전과 맞는지 확인한 뒤 적용합니다.

    1PC에서는 한 번 설치해 같은 PC에 배정된 자율주행·운영·부가 패키지를 실행합니다. 분산 구성에서는 각 PC에서 해당 장비를 선택해 설치합니다. PC 선택은 두 번째 PC를 필수로 요구하는 단계가 아니며, 동시 실행할 기능은 플랫폼 배정을 따릅니다.

    이 흐름은 새 PC 설치 계약을 포함한 배포 버전부터 사용할 수 있습니다. 이전 역할별 묶음은 선택 없이 고정된 PC에 설치합니다. 배정과 연산 분리의 기준은 ECU 설치 설계를 따릅니다.

    이미 설치된 PC도 같은 채널의 상위 버전 묶음으로 업데이트할 수 있습니다. 차량을 안전하게 정차하고 자율주행·차량 제어를 종료한 뒤 furive service stop을 실행하고, 새 묶음의 ./bootstrap.sh를 실행합니다. 기존 furive-os-deploy 폴더를 삭제할 필요가 없습니다. 설치 위치와 보존 대상 설정을 이어받고, 이미 준비된 이미지와 호스트 도구를 재사용합니다. 버전 전환 후 설치가 실패하면 기존 전환 복구 절차로 이전 버전을 복원합니다.

    업데이트 채널이 다르거나 같거나 낮은 버전인 묶음은 업데이트에 사용하지 않습니다. 동일 버전의 설치 복구에는 furive setup --repair를 사용합니다. 중간 호환 버전이 필요한 경우에는 해당 버전을 먼저 설치하고 서비스 시작 뒤 일반 OTA가 묶음의 목표 버전까지 이어갑니다.

    한눈에 보는 흐름¶

    flowchart TD
  Start["./bootstrap.sh"] --> Check["PC · 설치 묶음 정보 확인"]
  Check --> PC["기존 PC 배정 유지 · 신규 PC만 선택"]
  PC --> Plan["설치·유지·건너뜀과 정확한 image·driver 등 주요 영향 표시"]
  Plan --> Agree{"한 번 승인"}
  Agree -->|아니요| Stop["변경 없이 종료"]
  Agree -->|예| Host["필수 도구 · Toolkit · DDS · Furive 준비"]
  Host --> GPU{"Furive가 NVIDIA driver를 설치했나?"}
  GPU -->|아니요| Service["Furive 서비스 시작"]
  GPU -->|예| Driver["마지막 작업: NVIDIA driver 설치"]
  Driver --> Reboot["10초 뒤 재부팅 · Ctrl+C로 취소 가능"]
  Reboot --> Final["다음 부팅: main clone · vcs import · container · colcon build"]
  Final --> Service
  Service --> Done["설치 완료"]

    단계별로 하는 일¶

    단계 하는 일 멈추는 경우
    사전 확인 Ubuntu와 CPU 아키텍처, 묶음 내용, 차량·역할을 읽기 전용으로 확인 다른 PC용 묶음, 손상된 파일
    PC 선택 신규 설치는 A-ECU 기본 선택, 기존 설치는 배정 재사용. 검증된 플랫폼의 PC 이름 사용 입력 중단, 설치 기록 충돌, 기존 PC와 다른 대상
    계획과 승인 설치·유지·건너뜀 항목, 정확한 Autoware image와 NVIDIA package, 재부팅 여부를 표시하고 y/N을 한 번 받음 대상을 확정할 수 없음, 사용자가 승인하지 않음
    PC 준비 필요한 검증 도구를 설치하고 서명·업데이트 경로를 확인한 뒤 Docker, 역할 설정, 자동 실행과 Furive 서비스를 준비 검증되지 않은 버전, 프로그램 설치 실패, 실행 중인 Docker 프로그램 때문에 안전한 Docker 재시작이 불가능함
    Autoware 호환 확인 플랫폼 또는 GPU 규칙으로 CUDA·driver·Docker 실행 이미지를 고르고, 새 PC만 제한된 자동 판정을 사용 호환표 밖의 GPU/OS, 가능한 driver 없음, 검증값 충돌
    적용 기존 설치는 보존 가능한 설정을 이어받고, 새 설치는 정해진 배포 위치에 준비 사용자가 수정한 배포 파일을 안전하게 보존할 수 없음
    시작 driver 변경이 없으면 서비스를 바로 시작. driver를 설치했으면 다음 부팅의 최종 작업이 성공한 뒤 시작 GPU나 Autoware container 최종 검증 실패

    설치가 중간에 실패하면 첫 오류를 해결한 뒤 같은 ./bootstrap.sh를 다시 실행합니다. 완료된 안전한 단계는 재사용하며, setup.sh, install.sh, run.sh를 대신 실행하지 않습니다.

    설치 중에는 진행률 옆에 현재 작업과 이유가 계속 바뀝니다. 이미 준비된 프로그램은 유지, 새로 받는 프로그램은 설치, 사용하지 않는 기능은 건너뜀으로 표시합니다. Autoware image는 정확한 이름과 함께 번들에서 불러오기, 로컬 검증본 재사용, 레지스트리에서 받기 중 실제 동작을 보여줍니다. 승인 뒤 image나 NVIDIA package 후보가 달라지면 다른 대상을 설치하지 않고 중단합니다.

    패키지 이미지는 이미지 2/5처럼 현재 순서와 완료 후 남은 개수를 표시합니다. 전체 설치 진행률과 별도로 다운로드, 압축 해제, 불러오기의 처리량·속도·예상 시간을 보여줍니다. 예상 시간은 현재 확인된 레이어의 남은 용량 합계와 합산 처리속도로 계산하므로 새 레이어가 발견되면 바뀔 수 있습니다. 발견된 레이어 중 용량을 모르는 것이 있으면 남은 시간 계산 중으로 표시합니다. 새 레이어가 처음 보고한 용량은 속도 측정에서 제외합니다. 다운로드가 100%여도 압축 해제와 저장이 남을 수 있으며, Docker가 성공적으로 끝나야 다음 이미지로 넘어갑니다. 10초 이상 출력 변화가 없으면 마지막 변경 이후의 대기 시간과 남은 시간 계산 불가를 표시합니다. 대기 표시만으로 실패를 뜻하지는 않습니다.

    묶음이나 이전 설치 시도로 정확히 같은 digest의 패키지 이미지가 이미 준비되어 있으면 레지스트리 인증·다운로드 없이 재사용합니다. 최초 설치에 필요한 이미지가 없으면 다운로드는 필요합니다. 설치 후 일반 시작은 준비된 로컬 버전을 먼저 실행합니다. OTA 다운로드와 사전 빌드는 별도 공간에서 진행하며, 준비가 끝난 업데이트만 다음 재시작에 적용합니다.

    NVIDIA driver가 필요한 main PC¶

    설치기는 ubuntu-drivers autoinstall을 사용하지 않습니다.

    • 1차로 별도 호환표에서 OS, CPU 아키텍처, GPU Compute Capability, Autoware CUDA와 driver 하한을 정확히 맞춥니다.
    • 아직 driver가 없어 GPU 상세값을 읽을 수 없을 때만, 호환표와 실제 GPU 지원 설치 파일 후보의 공통 범위에서 정확한 이름과 버전을 자동 선택합니다.
    • 표에 없거나 재부팅 뒤 GPU가 연결된 Docker 실행 시험을 통과하지 못하면 Autoware 설치를 중단합니다.

    이미 기준을 만족하는 driver는 바꾸지 않습니다. 교체가 필요하면 이유, 기존 driver와 설치할 driver를 보여주며 시작할 때 받은 한 번의 승인 범위에서 계속합니다. 상세 규칙과 표를 바꾸는 방법은 Autoware 호환 기준을 따릅니다.

    Furive가 driver를 설치하면 NVIDIA Toolkit·DDS·credential·서비스 등록을 먼저 끝냅니다. 화면을 구동하는 driver를 바꾼 뒤 Toolkit이나 Docker 설정을 계속하지 않도록 driver 설치를 마지막 큰 작업으로 실행하고 10초 뒤 재부팅합니다. 카운트다운 중 Ctrl+C를 누르면 재부팅만 취소할 수 있습니다. 다음 부팅에서는 로그인 전에 지정된 Furive 사용자로 GPU 확인, furive_autoware_main clone, 하위 source vcs import, 선택한 base image를 이용한 Furive Autoware container build와 colcon build를 마칩니다. 로그인하면 같은 진행률 형식의 최대화 터미널이 현재 단계를 보여줍니다. 비밀번호를 저장하거나 자동 로그인을 켜지 않고, 추가 sudo 입력도 받지 않습니다. 이 작업이 실패하면 Furive 서비스가 먼저 시작되지 않습니다.

    Secure Boot를 사용하는 PC는 운영체제가 재부팅 중 NVIDIA kernel module의 MOK 등록을 요구할 수 있습니다. 이 화면은 PC 자체의 보안 절차라 설치기가 대신 입력할 수 없습니다.

    설치 뒤 확인¶

    정상 설치는 별도 실행 명령이 필요 없습니다. 문제가 있을 때만 확인합니다.

    furive status
furive service logs

    furive status는 Furive 서비스·업데이트 상태와 함께 main PC의 Autoware CUDA 매핑, driver 기준과 현재 충족 여부를 보여줍니다. GPU driver가 없어도 GPU를 쓰지 않는 Furive OS 기능과 Docker 외의 일반 기능은 사용할 수 있습니다. 새 docker 그룹 권한은 새 로그인 세션이나 재부팅 뒤 사용자의 docker ps 같은 명령에도 적용됩니다.

    PC에 설치되는 package, 그룹, 파일과 서비스의 전체 목록이 필요할 때만 호스트 영향을 확인합니다.
