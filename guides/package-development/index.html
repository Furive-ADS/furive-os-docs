    🧩 프로그램을 Furive에 연결하기¶

    이미 독립 저장소에서 실행되는 프로그램을 Furive에 연결할 때 이 문서를 사용합니다. Furive에서는 이렇게 연결한 프로그램을 패키지라고 부릅니다. Autoware package나 ROS package를 새로 만드는 절차는 아닙니다.

    처음 연결할 때의 흐름은 하나입니다.

    flowchart LR
  Program["① 독립 프로그램<br/>실행·테스트 확인"] --> Contract["② package.yaml · run.sh<br/>연결 정보 추가"]
  Contract --> Add["③ commit · push 후<br/>furive package add"]
  Add --> Run["④ furive package run<br/>실행·로그 확인"]
  Run --> Check["⑤ furive package check<br/>연결·테스트 검사"]

    대상 패키지 통합 개발자

    시작 위치 독립 저장소 + Furive source

    완료 기준 실행·연결 규칙·테스트 확인

    활용 팁

    이름·버전과 실행 파일부터 연결하세요. Docker·장치·의존성처럼 기본값과 다른 요구만 설정에 추가합니다.

    1. 프로그램과 테스트를 먼저 준비하기¶

    Furive에 연결하기 전에 원래 저장소에서 프로그램의 빌드와 단독 실행을 확인합니다. Furive는 프로그램 코드, Dockerfile이나 테스트를 대신 만들지 않습니다.

    저장소에는 실제 기능을 확인하는 테스트가 하나 이상 있어야 합니다. 정상 입력과 대표 실패 입력을 실행해 API 응답, ROS 메시지, 파일 또는 계산 결과처럼 밖에서 관찰되는 결과를 확인합니다. 프로그램이 살아 있거나 코드 문구가 존재한다는 검사만으로는 충분하지 않습니다. 자동으로 찾는 형식은 패키지가 소유하는 테스트에 있습니다.

    2. 이름과 실행 방법 알려주기¶

    저장소 루트의 package.yaml에는 먼저 두 값만 적습니다.

    name: hello-sensor
version: 0.1.0

    다른 필드를 생략하면 edge에서 run.sh를 실행하는 일반 패키지가 되며, 프로그램이 실행 중인지 확인합니다.

    run.sh는 필요한 환경을 준비한 뒤 마지막에 실제 프로그램을 exec합니다.

    #!/usr/bin/env bash
set -euo pipefail

PACKAGE_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
exec "$PACKAGE_DIR/build/service" "$@"

    실행 파일 경로와 빌드는 프로그램 저장소가 담당합니다. run.sh 안에 무한 재시작, pkill, 자체 업데이트, 로그 순환이나 다른 패키지 제어를 넣지 않습니다. 시작·중지·상태 확인·재시작은 공통 프로그램 실행 관리자(Package Manager)가 한 번만 담당합니다.

    Docker, main 실행, 장치, 의존성처럼 기본값과 다른 요구가 있을 때만 package.yaml에 항목을 추가합니다. 필드 이름과 예시는 프로그램 연결 설정을 봅니다.

    3. 독립 저장소를 연결하기¶

    package.yaml, run.sh와 테스트를 독립 저장소에 commit하고 원격 저장소에 push한 뒤 Furive OS 개발 저장소의 최상위 폴더에서 연결합니다.

    ./furive package add <repository-url>

    이 명령은 기존 저장소를 package/plugin 아래 연결 저장소(Git submodule)로 추가합니다. 파일을 복사하거나 같은 프로그램의 두 번째 저장소를 만들지 않습니다. 아직 push하지 않은 로컬 파일은 package add가 가져올 수 없습니다.

    4. 패키지 하나 실행하고 로그 보기¶

    ./furive package run hello-sensor

    터미널에는 Furive의 시작·중지 안내만 표시됩니다. 프로그램의 일반 출력과 오류 출력(stdout/stderr)은 다음 파일에 기록됩니다.

    logs/<정규화된-패키지명>.log

    프로그램 실행 관리자는 패키지명의 하이픈을 밑줄로 바꾸므로 이 예시의 로그는 logs/hello_sensor.log입니다. 실행 중 로그를 볼 때는 다른 터미널에서 확인합니다.

    tail -f logs/hello_sensor.log

    실행한 터미널에서 Ctrl+C를 누르면 패키지와 이번 실행이 시작한 의존 패키지가 역순으로 종료됩니다.

    5. 연결 정보와 테스트 확인하기¶

    ./furive package check

    이 명령은 모든 연결된 프로그램의 package.yaml을 먼저 검사하고, 유효할 때 각 저장소의 테스트를 실행합니다. 중복 이름, 잘못된 필드, 없는 실행 파일, 테스트 없음과 테스트 실패는 모두 실패입니다.

    Furive OS 변경과 함께 공유할 준비가 끝나면 전체 검사도 실행합니다.

    ./furive check

    6. 차량 구성에 포함하기¶

    패키지 단독 실행과 검사가 끝난 뒤에만 해당 플랫폼의 main 또는 edge 패키지 목록에 이름을 추가합니다. 플랫폼 구성은 차량 플랫폼 만들기, 한 차량 적용은 차량 업데이트를 따릅니다.

    완료 조건은 네 가지입니다.

    • 독립 저장소에서 프로그램과 실제 기능 테스트가 통과한다.
    • package.yaml과 run.sh의 최소 정보만으로 동작한다.
    • furive package run으로 시작하고 Ctrl+C로 함께 종료된다.
    • 정규화된 로그 파일을 확인했고 furive package check가 통과한다.
