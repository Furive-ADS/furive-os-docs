    운영을 하나로.¶

    설치·실행·상태 확인·업데이트를 함께 관리합니다.

    01 / DEVELOP

    쓰던 GitHub 저장소 그대로¶

    Python 녹화 프로그램, 웹 UI, 센서 드라이버. 각 팀은 자기 도구로 개발하고 실행 방법을 패키지로 연결합니다.

    02 / OPERATE

    차량 PC의 실행·상태를 한곳에서¶

    설치 때 배정한 PC에서 패키지를 시작하고, 실행 상태와 로그를 같은 운영 화면에서 확인합니다.

    03 / UPDATE

    새 버전 적용부터 복구까지¶

    새 버전을 준비·검증한 뒤 적용합니다. 적용 후 정상 확인에 실패하면 이전 정상판으로 복구합니다.

    정지선 앞 감속이 늦다면,
    수정한 코드를 차량까지.¶

    예시: 정지선 앞에서 늦게 감속하는 자율주행 동작을 개선합니다.

    기존 Autoware 배포 절차로 구성한 설명용 사례입니다. 특정 차량의 장애나 완료된 시험 결과가 아닙니다.

    01 / DEVELOP IN GITHUB

    쓰던 GitHub 저장소에서,
    감속 로직을 고칩니다.¶

    자율주행 개발자는 Autoware 작업 공간에서 문제를 재현하고, 정지선에 접근할 때 감속을 시작하는 로직을 수정합니다. 같은 조건의 회귀 테스트와 빌드로 변경을 확인합니다.

    자율주행 알고리즘과 테스트는 Autoware 개발팀이 소유합니다. Furive OS에서는 지원 플랫폼이 사용할 정확한 Autoware 버전(commit)을 지정합니다.

    Autoware 빌드·버전 확인 방법 ↗

    02 / CHECK · BUILD · REPORT

    수정한 코드가,
    배포할 수 있는 버전으로.¶

    Autoware 변경을 검증한 뒤 사용할 commit을 Furive OS 통합 PR에 반영합니다. GitHub Actions는 공통 코드·설정과 영향받는 패키지의 테스트를 실행하고 결과를 남깁니다.

    통과 후 릴리즈를 실행하면 지정한 Autoware 버전을 담은 차량 배포본을 생성합니다. 업데이트 경로를 검사하고 서명된 시험판을 발행합니다. Autoware 자체 빌드·주행 검증 결과는 별도로 확인합니다.

    입력 검증한 Autoware commit → 결과 검사 보고서 + 해당 버전을 지정한 시험판

    실제 CI/CD 단계와 자동 검사 범위 ↗

    03 / OVER-THE-AIR UPDATE

    새 소프트웨어가,
    OTA로 차량에 도착합니다.¶

    시험 차량 한 대에 test 업데이트를 배정합니다. 안전하게 정차한 정비 시점, Autoware 업데이트가 켜져 있으면 지정한 소스 버전으로 동기화하고 필요한 빌드를 수행합니다.

    새 버전의 정상 상태를 확인한 뒤 업데이트를 확정합니다. 확인에 실패하면 이전 정상판으로 복구합니다.

    시험 구간에서 감속 시작 시점과 정지 위치를 확인합니다. 자율주행 기능과 복구 시험을 마친 뒤 normal 배포로 넓힙니다.

    시험 차량 업데이트와 정식 배포 ↗

    ON THE VEHICLE / CHECK THE RESULT

    버전을 확인하고,
    감속·정지를 검증합니다.¶

    Launcher에서 현재 Autoware 버전이 배포 버전과 일치하는지 확인합니다. 이어 통제된 시험 구간에서 접근 속도·감속 시작 시점·정지 위치를 확인합니다.

    Furive OS가 소프트웨어의 전달·실행·복구를 연결하면, 개발팀은 수정한 자율주행 동작의 검증에 집중할 수 있습니다.
